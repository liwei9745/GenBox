# P4 服务器确认码配对体验策略

**日期：** 2026-07-24
**证据范围：** 本文的产品研究为公开文档研究；实现和测试证据只允许标记为 `LOCAL`。本轮不执行真实 SSH 配对、VPS、远程容器或网络部署；浏览器检查只允许使用本地运行时。

## 1. 目标和边界

配对的唯一任务是确认“这个已保存的目标，确实返回了用户在可信 SSH 会话中看到的同一台服务器主机身份”。它不登录服务器、不验证 SSH 密码、不执行部署命令，也不证明 VPS 所有权。完成后只保存后端重新探测并校验过的主机密钥算法和 `SHA256:` 指纹。

本轮服务对象是第一次接触 SSH 的个人用户。默认路径不要求用户阅读或比较指纹，而是把可信 SSH 会话产生的一次性证明包装为“服务器确认码”；用户只需复制确认工具、在自己已登录且信任的终端运行、再粘贴一行确认码。配对材料（挑战、命令、响应、指纹候选）只存在于短时请求和页面内存中，不进入浏览器存储、任务记录、日志、截图、URL 或 Git。

这不是把首次信任改成浏览器的“点击即信任”：浏览器自己读取到的 SSH 主机键不能证明它没有遭遇目标替换。当前没有已集成的服务商账户验证或本机受信任助手时，可信 SSH 会话仍是最短且不降低安全性的信任来源。服务商控制台、既有 `known_hosts` 或手动核对仅作为高级恢复路径，不进入默认步骤。

## 3. 设计策略

### 3.1 单一主任务和步骤状态

面板标题固定为“确认这台服务器”。说明只用一句话：`在你平时用来登录这台服务器的终端中完成确认。GenBox 不会要求你输入密码或私钥。` 上方只保留三个编号步骤：

1. **生成确认码**：点击主按钮“开始确认”；加载期间禁用重复请求。系统生成短时一次性配对材料，但不在页面上显示指纹或协议名称。
2. **复制确认工具并运行**：显示只读单行工具和图标复制按钮，按钮文案为“复制”；复制成功后自动将焦点移到下一步输入框。用户只需在已登录且信任的 SSH 终端粘贴并运行。
3. **粘贴确认码**：输入框标签为“确认码”，placeholder 不暴露协议前缀；有内容后启用高显著主按钮“确认这台服务器”。前端将输入按固定协议提交，提交期间禁用输入和按钮。

用户永远不需要输入、阅读或比较 `SHA256:` 指纹。固定工具在可信终端读取主机公开身份，并生成一次性确认码及摘要证明；终端输出和浏览器提交都不包含完整指纹。后端以保存的算法、完整指纹和挑战值复算摘要，再继续原有重新探测与 CAS 校验。步骤状态通过已完成、当前步骤、需处理的提示和文字表达，不能只靠颜色；窄屏改为纵向堆叠，按钮保持可触控宽度。复制失败时保留文本选中能力并给出“手动选中后复制”的恢复提示。

### 3.2 生命周期和恢复

- **空闲：** 显示“开始确认”以及“不会保存密码、私钥或确认码”。
- **加载：** 显示“正在准备一次性确认”，阻止重复请求。
- **等待确认：** 显示确认工具、倒计时和确认码输入框；页面内存记录过期计时器。
- **成功：** 清空工具、确认码和计时器，只显示“这台服务器已确认”；随后引导进入凭据步骤。该文案不声明已登录、拥有 VPS 或完成部署。
- **失败：** 后端错误映射为安全、可行动的中文提示；不回显原始确认码、指纹或异常堆栈。可点击“重新开始”，不能在失败后复用确认材料。
- **过期/取消：** 清空所有临时字段，保留已保存目标但不保存任何身份，主按钮恢复为“重新开始确认”。用户主动取消时，浏览器先清除页面材料并把焦点还给重新开始，再仅以一次性配对编号请求本机后端废止对应记录；端点不接收回执、凭据、目标或主机身份，也不泄露记录是否曾存在。清理请求未确认时，只显示可行动的通用提示，且不影响后来新建的配对。
- **目标被编辑或切换：** 立即使旧请求和旧配对失效，隐藏配对面板，要求对新身份重新开始。与主动取消相同，页面清理会仅以旧配对编号尽力废止本机记录；过期也走同一清理路径，避免浏览器状态先于后端短期记录失效。

后端继续执行主机密钥算法白名单、完整 `SHA256:` 格式校验、挑战单次消费、目标身份版本绑定、完成前重新探测和 compare-and-swap 保存。确认码只传递一次性证明，不能替代这些检查；前端状态也不能替代这些检查。

### 3.3 安全文案和数据边界

- 只说“服务器已确认”，不说“已登录”“已拥有 VPS”或“已安全”。
- 明确“不要在这里输入 SSH 密码、私钥、私钥口令或 sudo 密码”；确认码不是密码，凭据字段继续使用 `autocomplete=off`，不进入配对请求。
- 不显示或持久化原始终端输出；输入框只称“确认码”，不暴露固定协议前缀、算法或指纹。
- 错误提示使用通用恢复动作：检查可信终端、确认目标未被重建、重新生成；不泄露 host、IP、用户名、指纹或服务器输出。
- 不提供关闭 host-key 检查或自动接受变更键的控件。

### 3.4 可访问性和窄屏

- 使用真实 `button`、`label`、`textarea`，状态区域带 `role=status` / `aria-live=polite`；确认码输入框提供可见标签和简短示例说明，而不以协议细节作为提示。
- 步骤列表使用可读文本，不只依赖颜色；按钮在键盘焦点下有明显轮廓，复制后焦点仍在复制按钮。
- 命令和响应文本框允许换行显示、`overflow-wrap:anywhere`，不让长 token 撑破布局；窄屏下命令和按钮纵向排列。
- 提交按钮在输入为空、加载中、离线、过期时均 disabled；Escape/取消通过“重新开始”清空内存状态。取消、过期或提交被拒绝后，键盘焦点回到可见的重新开始按钮，避免留在已隐藏的输入或操作控件上。

### 3.5 没有可信终端时的恢复

“没有已登录终端？”始终作为默认面板的次要入口，而不是等到确认失败后才出现。展开后只说明三条安全来源：服务商控制台、已有 `known_hosts` 记录，或管理员提供的可信公开主机身份。它明确要求用户不要开始确认、不要粘贴密码或私钥。

“打开高级核对”只展开现有高级区域并把键盘焦点移到手动入口；它不读取主机、不调用 SSH endpoint、不创建挑战，也不保存任何输入。Escape 收起帮助并将焦点还给帮助按钮。这样新手能找到下一步，同时不会把帮助行为误解成已连接服务器。

## 4. 本地实现清单

1. 将面板文案、可访问标签、状态和主按钮改为“服务器确认码”模型；保留现有固定 helper、可信终端边界和高级恢复路径。
2. 增加前端短时过期计时器和明确的过期状态，过期自动清理临时材料并允许重新开始；用户主动取消同时废止本机内存中的对应一次性记录。
3. 对复制成功、复制失败、确认码提交加载、后端拒绝、目标切换分别覆盖 focused tests；测试同时断言页面不显示指纹、算法或协议前缀。
4. 验证默认帮助入口能无网络副作用地展开高级恢复路径、保留键盘焦点并可用 Escape 收起；再用 Node 语法检查、配对后端 pytest、静态 UI 测试和完整本地测试验证。浏览器只访问 `http://127.0.0.1:8892/#/extensions`，证据标记为 `LOCAL`。

## 5. 剩余风险与阻塞

- 可信 SSH 会话仍是用户提供的初始信任锚点，不能证明 VPS 归属。没有可信会话时，默认确认码路径不可用；用户必须走服务商控制台、既有 `known_hosts` 或手动核对。要做到完全免终端，必须另行设计并集成可验证的服务商账户授权或本机受信任助手，不能用浏览器自动接受主机键替代。
- 本轮不验证真实 SSH、VPS 隔离、远程容器、私网链路或生产非变更；这些仍是 L2 及后续门槛。
- 浏览器剪贴板权限可能被拒绝，因此必须保留手动选择复制的恢复路径。

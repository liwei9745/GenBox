# Phase 6-9 Gate Reference

Use this compact reference with `docs/PHASE6-9-DELIVERY-GATES.md`.

## Phase 6: Cleanup

Require default-off policy, validated receiver receipt, matching current
SHA-256, storage-rooted target checks, durable audit state, dry run, focused
adversarial tests, independent review, and explicit synthetic isolated-target
authorization. Any missing, changed, ambiguous, or failed condition retains
the source.

## Phase 7: Clean Redeployment

Require a frozen candidate, sanitization of tree/history/artifacts, a clean
owner-repository clone, fresh credentials, build/deploy only from that clone,
repeated transfer acceptance, and a separate production non-mutation check.

## Phase 8: Upstream Delivery

Require verified Phase 7 evidence. Split contributions into foundation,
generation/batch, and scheduler/cleanup slices. Include contract version,
compatibility, migration, tests, disable/rollback path, and placeholders only.

## Phase 9: Service Adapter

Require a dossier for provenance/license, supported capability, typed config,
secrets, isolation, network/health, operations, and tests. Backend capability,
not catalog metadata, controls every executable UI action.

## Labels

- `VERIFIED`: dated sanitized command or observation.
- `USER-CONFIRMED`: dated human action or approval with exact scope.
- `EXTERNAL`: another system, repo, CI, or reviewer must supply it.
- `UNVERIFIED`: no adequate evidence; do not guess.
